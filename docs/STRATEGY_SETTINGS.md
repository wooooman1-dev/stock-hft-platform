# 자동전략 설정과 저장

## 구현 범위

자동전략의 다음 값은 화면과 API에서 변경할 수 있습니다.

- 진입 최소 신뢰도: 0~100%
- 청산 최소 신뢰도: 0~100%
- 최대 진입 스프레드: 1~20틱
- 진입 주문 수량: 1~100주
- 재진입 대기시간: 1~600초
- 손절률: 빈칸이면 OFF, 0.01~100%
- 익절률: 빈칸이면 OFF, 0.01~100%
- 트레일링 스톱: 빈칸이면 OFF, 0.01~100%
- 최대 보유시간: 빈칸이면 OFF, 1초 이상의 정수

API와 저장 파일에서는 손절·익절·트레일링 스톱을 정수 basis point로 저장합니다. `100bps = 1%`입니다. 최대 보유시간은 밀리초 정수로 저장합니다.

기존 설정 파일에 네 위험청산 필드가 없으면 모두 `null`로 보완하며 자동으로 활성화하지 않습니다.

## 위험청산 기준

위험청산은 모의 자동전략이 ON인 동안에만 평가합니다. 자동전략이 OFF이거나 킬 스위치가 ON이면 실행하지 않습니다.

현재 긴 포지션만 지원하며 다음 기준을 사용합니다.

- 손절·익절: 현재가와 포지션 평균단가의 수익률
- 트레일링 스톱: 포지션 진입 후 관측한 최고 현재가 대비 하락률
- 최대 보유시간: 포지션이 0주에서 양수로 바뀐 최초 시각부터 경과시간

여러 조건이 같은 시점에 충족되면 다음 순서로 하나만 선택합니다.

```text
손절
→ 트레일링 스톱
→ 익절
→ 최대 보유시간
→ 일반 매도신호
```

위험청산은 재진입 대기시간보다 우선합니다.

## 전체 포지션 청산

위험청산과 일반 매도신호는 모두 현재 보유수량 전체를 시장가 IOC로 제출합니다.

청산 전에 열려 있는 매수·매도 지정가 주문을 모두 취소합니다. 이는 예약수량 때문에 전체 청산이 거절되거나, 청산 후 대기 매수 주문이 체결되어 포지션이 다시 생기는 것을 방지하기 위한 규칙입니다.

표시 호가의 매수 잔량이 부족하면 시장가 IOC는 보이는 수량만 부분 체결하고 나머지를 취소합니다. 포지션이 남아 있고 위험조건이 계속 충족되면 다음 시장 갱신에서 다시 청산을 시도합니다.

## 저장 위치

기본 저장 파일:

```text
.pulsehft/strategy-settings.json
```

환경변수 `PULSEHFT_DATA_DIR`를 지정하면 해당 디렉터리에 저장합니다.

저장은 임시 파일을 먼저 작성한 뒤 최종 파일명으로 교체합니다. 파일이 없으면 문서화된 기본값을 사용합니다. JSON이 손상됐거나 값이 허용범위를 벗어나면 조용히 기본값으로 덮지 않고 서버 시작을 중단해 오류를 노출합니다.

## 재시작 안전 정책

설정값은 재시작 후 복원되지만, `모의 자동전략 활성화` 상태와 모의 포지션·포지션 위험 추적 상태는 저장하지 않습니다.

```text
서버 재시작
→ 전략 설정 복원
→ 자동전략은 OFF
→ 모의계좌와 포지션 위험 추적은 초기 상태
→ 사용자가 다시 직접 활성화
```

## API

```text
GET  /api/strategy/settings
PUT  /api/strategy/settings
POST /api/strategy/settings/reset
```

`PUT`은 전체 또는 일부 설정을 받을 수 있으며 알 수 없는 필드와 허용범위를 벗어난 값은 HTTP 400으로 거절합니다.

## 결정적 위험청산 검증 API

손절·익절·트레일링 스톱을 무작위 시뮬레이터 움직임에 의존하지 않고 검증하기 위한 로컬 전용 API가 있습니다. 일반 실행에서는 존재하지 않는 경로처럼 HTTP 404를 반환합니다.

다음 조건을 모두 만족해야 사용할 수 있습니다.

1. 서버 시작 전에 `PULSEHFT_ENABLE_VERIFICATION_API=true`를 명시
2. 요청이 `127.0.0.1`, `::1` 또는 IPv4-mapped loopback에서 들어옴
3. 현재가격이 실제 호가 단위에 맞음
4. 검증용 호가 잔량과 시각이 서버 검증을 통과함

PowerShell 시작 예시:

```powershell
$env:PULSEHFT_ENABLE_VERIFICATION_API = "true"
npm start
```

검증용 시장 틱 요청:

```text
POST /api/verification/market-tick
```

```json
{
  "lastPrice": 69000,
  "depthSize": 1000
}
```

첫 검증용 시장 틱이 들어오면 200ms 무작위 시장 타이머를 즉시 정지합니다. 이후 서버를 재시작할 때까지 검증용 가격과 호가만 적용되므로 자동전략 ON 요청과 강제 가격 요청 사이에 일반 시뮬레이터 틱이 끼어들지 않습니다. 반환 스냅샷의 `system.verificationMode`와 `system.marketTimerPaused`가 `true`인지 확인할 수 있습니다. 일반 모드 스냅샷에는 이 두 검증 전용 속성을 포함하지 않습니다.

각 요청은 지정한 현재가격을 중심으로 10단계 검증용 표시호가를 만들고, 열린 주문 처리와 자동전략 평가를 한 번의 동기 실행 흐름으로 완료한 뒤 스냅샷을 반환합니다. 설정을 변경하거나 자동전략을 강제로 켜지는 않습니다.

검증이 끝나면 서버를 종료하고 환경변수를 제거합니다.

```powershell
Remove-Item Env:PULSEHFT_ENABLE_VERIFICATION_API -ErrorAction SilentlyContinue
```

이 API는 내부 모의체결 검증용이며 실제 증권사 시세 또는 주문 모드에서는 사용하지 않습니다.

## 아직 포함하지 않는 항목

- 하루 최대 거래 횟수
- 연속 손실 제한
- 장 종료 청산
- 수수료·세금을 포함한 순손익 기준 청산
- 실제 증권사 주문·체결 상태 연동
