# 모의계좌 자동매매 설계 (v1)

## 목적

`evaluateAutoStrategy`를 KIS 모의계좌에 연결해, **수익성 판정에 쓸 표본을 실제 브로커 조건에서 쌓는다.**

내부 시뮬레이터(`PaperTrader`)로는 잡히지 않는 것 — 브로커 응답 지연, 부분체결, 거절, 미체결, `UNKNOWN_RESULT`, 재시작 복원 — 이 검증 대상에 포함된다.

이 문서는 v1 범위만 정의한다. 실전 연결은 별도 승인 사항이며 이 문서의 범위가 아니다.

## 설계 원칙

1. **모의에서 검증된 것만 실전으로 넘긴다.** 모의 체결은 실제보다 관대하므로 모의 수익률은 상한선으로 취급한다.
2. **비용을 설계에 명시적으로 넣는다.** 왕복 약 22.8bp(거래세 20 + 수수료 2.8)를 넘지 못하는 진입은 애초에 하지 않는다.
3. **v1은 충실도를 최적화보다 우선한다.** 모의와 실전의 괴리를 키우는 선택은 피한다.
4. **기존 부품을 재사용한다.** 새 전략을 만들지 않는다. 배선과 게이트만 추가한다.

---

## 1. 종목 선택과 포지션 수

**동시 보유 1종목.** `evaluateAutoStrategy`가 `positionQuantity === 0`을 진입 조건으로 갖는 단일 포지션 설계이고, v1에서 이를 바꾸지 않는다.

종목은 고정하지 않고 매 평가 시점에 추천 스캐너 후보에서 고른다.

```
포지션 없음  → 후보 중 진입 게이트를 통과한 것 하나를 선택 (점수 최고순)
포지션 있음  → 보유 종목만 평가. 다른 후보는 무시
```

동시 다종목은 v2로 미룬다. 표본 수는 늘지만 포지션 관리·리스크 합산·자금 배분이 전부 새로 필요하고, v1의 검증 대상이 아니다.

## 2. 진입 게이트

기존 `ENTRY_READY`에 **비용 문턱**을 추가한다. 이게 v1의 핵심 설계 기여다.

```
진입 조건 = ENTRY_READY
          AND 예상순익 >= minimumNetEdgeBps
          AND 쿨다운 경과
          AND 일일 주문/손실 한도 여유
```

예상순익 계산:

```
expectedNetBps = takeProfitBps
               - buyCommissionBps      (1.41)
               - sellCommissionBps     (1.41)
               - sellTaxBps            (20)
               - spreadBps             (진입 시점 실측)
               - slippageBps           (예상 1틱)
```

`minimumNetEdgeBps` 기본값 **50bp**. 즉 비용을 다 빼고도 0.5% 이상 남을 국면에만 진입한다.

이 게이트가 없으면 왕복 비용이 기대 수익을 넘는 거래를 반복하게 된다. 2026-08-03 기록 데이터에서 관측된 최대 변동이 2틱(25.5bp)인데 왕복 비용이 3.6틱이었다.

**스프레드가 넓으면 자동으로 걸러진다.** 스프레드가 클수록 `expectedNetBps`가 줄기 때문에 별도 스프레드 상한과 이중으로 작동한다.

### 2-1. 추가 진입 필터 (2026-10-02)

036930(주성엔지니어링) 매매 손실(순손익 −12,196원)을 분석해 추가했다. 그 매매는 아래 조건을 모두 어겼다. 당일 VWAP −193bp, 체결강도 91.8로 하락 중이었고, ENTRY_READY는 2분 40초만 유지됐으며, 점심시간이었고, 손절 100bp가 4.9틱이었다.

| 설정 | 기본값 | 막는 것 |
|---|---|---|
| `entryMinimumExecutionStrength` | 100 | 매도 우위(체결강도 100 미만)에서의 진입 |
| `entryMinimumVwapExtensionBps` | −50 | 당일 VWAP보다 크게 아래(하락 추세)에서의 반등 매수 |
| `entryConfirmMs` | 30,000 | 한 순간만 맞은 신호. 연속 유지가 끊기면 처음부터 다시 잰다 |
| `noEntryWindows` | 09:00–09:10, 11:30–13:00, 14:50–15:30 | 장 초반·점심·마감 직전 진입 |
| `minimumStopTicks` | 6 | 손절폭이 호가 몇 틱밖에 안 되는 고가주 |
| `minimumRewardRiskRatio` | 1.5 | (익절−비용−스프레드) ÷ (손절+비용+스프레드)가 낮은 진입 |
| `maxConsecutiveLossesPerDay` | 3 | 오늘 비용 차감 후 연속 손실 뒤의 추가 진입 |

연속 손실 제한은 주문 서비스의 `maxConsecutiveLosses`(킬 스위치)를 쓰지 않는다. 킬 스위치는 보호 청산 매도까지 막기 때문이다. 여기서는 신규 진입만 멈춘다.

호가단위는 후보의 `price.tickSize`, 호가 스프레드 ÷ 스프레드 틱 수, KRX 호가가격단위 순서로 정한다. 스캐너 후보에는 `price.tickSize`가 없다.

설정 변경 효과는 `npm run backtest:auto-trading -- <연구 기록.jsonl...>`로 확인한다. 같은 기록에 이전 규칙과 새 규칙을 나란히 돌린다(실제 `KisPaperAutoTrader` 사용, 시장가는 최우선 호가에 즉시 체결 가정).

## 3. 수량 산정

모의에서는 사이징 로직도 검증 대상이다. 고정 수량 대신 자본 비율로 계산한다.

```
목표금액 = min(equity × positionSizeRatio, limits.maxOrderValue)
수량     = floor(목표금액 / 현재가)
수량     = min(수량, limits.maxOrderQuantity)
수량 < 1 이면 진입하지 않는다
```

기본값 `positionSizeRatio = 0.1` (자기자본 10%). 모의계좌 한도는 1회 10주 / 100만원이므로 실질 상한은 한도가 결정한다.

주가가 목표금액보다 비싸 1주도 못 사는 종목은 진입 대상에서 제외된다. 이는 의도된 동작이다.

## 4. 청산

`positionRiskTracker`의 기존 보호 청산을 사용한다. **현재 전부 `null`(비활성)이므로 값을 넣어야 한다.**

| 설정 | 기본값 | 근거 |
|---|---|---|
| `stopLossBps` | 100 | 손실 1%에서 끊는다 |
| `takeProfitBps` | 250 (2026-10-02, 150에서 상향) | 150일 때 비용·스프레드를 빼면 손절과 손익비가 약 1:1이라 승률 50% 이상이 필요했다 |
| `stopConfirmMs` | 2,000 | 손절선 아래 2초 유지 시 손절. 손절폭 2배 이상 빠지면 즉시 |
| `trailingStopBps` | 70 | 익절 전 되돌림 보호 |
| `maxHoldingMs` | 1,800,000 (30분) | 무한 보유 방지. 초단타 전제 유지 |

`takeProfitBps 150`은 `minimumNetEdgeBps 50`과 짝을 이룬다 — 150에서 비용 약 23bp와 스프레드를 빼면 문턱을 넘는다.

**장 종료 전 강제 청산.** 15:15에 미청산 포지션을 시장가로 정리한다. v1은 오버나이트 리스크를 검증 대상에 넣지 않는다.

## 5. 주문 유형

**진입·청산 모두 시장가 IOC.**

지정가 진입이 슬리피지를 줄이는 건 맞지만, **모의계좌의 지정가 체결이 실제보다 관대하다.** 모의는 호가에 닿으면 체결시켜 주는 반면 실전에서는 앞 물량에 밀려 미체결되거나 부분체결된다. 지정가로 검증하면 모의 성적이 실전으로 넘어가지 않는다.

시장가는 비용을 더 내지만 **모의와 실전의 괴리가 작다.** v1은 이 쪽을 택한다.

슬리피지를 실측한 뒤(§7) v2에서 지정가 진입을 검토한다.

## 6. 안전 정지

기존 `KisPaperOrderService.enforceSafety`가 이미 강제하는 것:

- 1회 수량·금액 한도
- 일일 주문 횟수 (기본 20건)
- 일일 손실 한도 (기본 100,000원)
- 연속 손실 (기본 3회)
- 킬 스위치, `UNKNOWN_RESULT` 발생 시 정지

v1에서 추가하는 것:

- **`UNKNOWN_RESULT` 발생 시 자동매매 즉시 중단.** 주문 상태가 불확실한데 다음 주문을 내면 안 된다. 사람이 해소할 때까지 멈춘다.
- **대사 불일치(`RECONCILIATION_MISMATCH`) 시 중단.** 같은 이유다.
- **시세 지연 시 진입 금지.** 호가·체결이 5초 이상 오래되면 신규 진입하지 않는다. 보호 청산은 계속 동작한다.

## 7. 측정

판정에 쓸 지표를 실행 저널에서 산출한다.

**정정(2026-09-11):** 초안에 "최대 낙폭이 없다"고 적었으나 사실과 다르다. `kisPaperPerformance.js`의 `equity` 블록에 `peak`, `maxDrawdownAmount`, `maxDrawdownPct`, `currentDrawdown*`이 이미 있고 `BROKER_EQUITY_SNAPSHOT` 기반으로 산출된다. 체결 괴리도 `fillModelComparison.js`로 이미 구현돼 있다.

실제로 빠져 있던 것은 **실현손익의 비용 반영**이었다. `realizedPnl = proceeds - costBasis`로 수수료와 거래세가 전혀 빠지지 않아, 총이익이 소폭 플러스인 전략이 실제로는 손실인데 통과해 보였다. 10주를 100,000원에 사서 100,200원에 팔면 총이익 2,000원이지만 거래세만 2,004원이라 순손실이다. `grossPnl`, `buyCost`, `sellCost`, `taxCost`, `totalCost`, `netPnl`을 거래별로 추가하고 집계에 `totalNetPnl`, `netWinRate`를 넣었다. `realizedPnl`은 기존 계약(총손익)을 유지한다.

| 지표 | 용도 |
|---|---|
| 실현 손익 (비용 차감 후) | 브로커 응답의 `estimatedFeesAndTaxes` 반영 |
| 거래 건수 | 표본 충분성 |
| 승률 / 평균 손익비 | 전략 성격 파악 |
| **최대 낙폭 (MDD)** | 실전 투입 가능 여부의 핵심 — 기존 구현 사용 |
| **체결 괴리** | 주문 시점 예상가 vs 실제 체결가. 실전 전환 시 손실될 성과의 크기 |
| 미체결·거절·`UNKNOWN_RESULT` 건수 | 시스템 안정성 |

체결 괴리는 `fill-comparison` 기능이 이미 있으나 카나리 범위에서 제외돼 있다. v1에서 켠다.

비용 모델은 자동매매 진입 게이트·내부 시뮬레이터·성과 지표가 **같은 값을 공유한다**(`loadPaperCostModel`). 어긋나면 "진입은 통과인데 판정은 실패"가 난다.

## 8. 판정 기준

**돌리기 전에 정한다.** 기준 없이 돌리면 좋았던 구간만 보게 된다.

아래는 제안값이며 사용자가 확정한다.

| 항목 | 제안 |
|---|---|
| 최소 표본 | 실현 거래 **100건** |
| 최소 기간 | **20 거래일** — 한 국면만 겪고 끝나지 않도록 |
| 통과 조건 | 비용 차감 후 누적 순익 > 0 **그리고** MDD가 투입 자본의 10% 이내 |
| 실패 조건 | MDD 20% 초과, 또는 100건 시점에 순익 음수 |
| 무효 조건 | `UNKNOWN_RESULT` 또는 대사 불일치 발생 — 원인 해소 후 재시작 |

**실패 조건을 미리 적어두는 것이 이 표의 핵심이다.**

## 9. 구현 범위

새로 만드는 것:

- `KisPaperAutoTrader` — 스캐너 후보와 `evaluateAutoStrategy`를 `KisPaperOrderService`에 잇는 오케스트레이터
- 비용 문턱 게이트 (§2)
- 자본 비율 수량 산정 (§3)
- 장 종료 전 강제 청산 (§4)
- MDD·체결 괴리 지표 (§7)
- 자동매매 on/off 및 상태 API

건드리지 않는 것:

- `evaluateAutoStrategy`, `positionRiskTracker` — 기존 로직 그대로 사용
- `KisPaperOrderService` — 기존 인터페이스로 호출만 한다
- 실전 경로(`kisLive*`) — v1 범위에서는 변경하지 않았다(2026-10-08에 실전 자동매매를 별도로 추가: `docs/KIS_LIVE_TRADING.md`)

## 10. 실전 전환 게이트

v1 통과 후에도 실전은 별도 승인 사항이다. 규모 확대 단계를 미리 정의해 둔다.

```
1주 고정        → 실행 정확성만 확인. UNKNOWN_RESULT 0건, 대사 CONSISTENT 유지
정액 소액        → 모의 §8 통과 + 실전 실행 정확성 확인 후
비율 사이징      → 실전 표본에서 체결 괴리가 모의 대비 허용 범위 내일 때
```

**2026-10-08 갱신**: 사용자가 위 단계를 앞당겨 실전 자동매매를 "소액 시험"(종목당 최대 20만원, 동시 3종목, 일 손실 한도 5만원)으로 직접 승인했다. `kisLiveConfig.js`의 `maxOrderQuantity` 설정 상한은 1에서 10,000으로 완화했고, 수동 주문의 1주 카나리는 런타임 검사로 그대로 유지한다. 실전 자동매매는 이 문서의 매매 로직을 같은 코드(`KisPaperAutoTrader`)로 쓰며 세 번째 게이트와 항상 꺼진 채 시작하는 규칙이 추가된다. 자세한 내용은 `docs/KIS_LIVE_TRADING.md`의 "실전 자동매매" 절. 모의 검증이 충분하다는 판정(§8)은 별도로 남아 있다.
