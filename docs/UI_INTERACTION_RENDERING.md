# Realtime UI Interaction Rendering

## 확인된 문제

PulseHFT는 SSE `snapshot` 이벤트를 받을 때마다 `public/app.js`의 `render()`가 `app.innerHTML` 전체를 교체합니다. 시뮬레이션에서는 이 갱신이 약 200ms 간격으로 발생합니다.

네이티브 `<select>` 옵션 팝업은 DOM 요소가 교체되는 순간 닫힙니다. 숫자 입력도 입력 도중 DOM이 교체되면 커서와 편집 흐름이 끊길 수 있습니다.

## 적용한 처리

`public/snapshotInteractionGuard.js`가 애플리케이션보다 먼저 로드되어 다음 입력을 조작하는 동안 SSE `snapshot` 콜백을 보류합니다.

- 주문 유형
- 주문 수량
- 지정 가격
- 진입 최소 신뢰도
- 청산 최소 신뢰도
- 최대 진입 스프레드
- 진입 주문 수량
- 재진입 대기시간

보호 입력 사이로 포커스가 이동하면 `relatedTarget`을 확인해 보호 상태를 유지합니다. 보호 입력 밖으로 이동하면 다음 이벤트 루프에서 최신 스냅샷 하나만 전달합니다. 종료 이벤트가 누락되면 최대 15초 후 안전하게 보호를 해제합니다.

보류 중 여러 스냅샷이 들어오면 오래된 스냅샷은 버리고 최신 스냅샷 하나만 유지합니다.

## 변경하지 않은 동작

- 일반 SSE 연결과 오류 처리
- 주문·전략 설정의 서버 API
- 시세·호가·체결·계좌 스냅샷 구조
- 서버 주문·체결 엔진

## 자동 검증

`server/test/snapshotInteractionGuard.test.js`에서 다음을 확인합니다.

1. 주문 유형 선택 중 최신 스냅샷만 보류
2. 주문 수량과 지정 가격 편집 중 렌더링 보류
3. 보호 입력 사이 이동 시 보호 유지
4. 입력 밖으로 이동한 뒤 0ms 타이머와 마이크로태스크 순서로 최신 스냅샷 전달
5. 키보드 `Escape`와 15초 안전 타임아웃에서 보호 해제
6. `snapshot` 이외의 EventSource 이벤트와 속성 전달 유지
